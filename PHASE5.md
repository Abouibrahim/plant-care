## Setup (Mohamed does the parts marked ★)

- [ ] ★ Run this once in the Supabase SQL editor (project → SQL Editor → New query → Run). It creates the `settings` table that holds the zone lists; `supabase/schema.sql` has the same lines for a fresh project. Until it is run, the "Sites and zones" card in Settings shows a notice and the record form falls back to the zones already used on plants.

  ```sql
  create table if not exists settings (
    key        text primary key,
    value      jsonb not null,
    updated_at timestamptz not null default now()
  );
  create trigger settings_updated before update on settings for each row execute function set_updated_at();
  alter table settings enable row level security;
  create policy owner_all on settings for all to authenticated using (true) with check (true);
  ```

## Build

- [x] French UI. `src/i18n/fr.ts` has every key of `src/i18n/en.ts`, typed against `Strings` so a missing or extra key fails `npm run typecheck`; French as used in Tunisia (arrosage, taille, paillage, savon noir), the language names shown in their own language. `src/i18n/index.ts` picks the table from `localStorage["plantcare.lang"]`, else from `navigator.language` (`fr*` → French), else English, and sets `<html lang>`. `as const` is dropped from `en.ts` so `Strings` widens the literals to `string`; the functions `api/_push.ts` and `api/_tasks.ts` keep importing `en` directly. Settings gets a "Language" card with English / Français; choosing one saves the key and reloads the app, since `t` is a constant imported everywhere (recorded in `docs/DECISIONS.md`). Profile text written by Claude stays in the language it was written in; dates follow the phone's locale.
- [x] CSV export. `src/lib/csv.ts`: RFC 4180 quoting, CRLF line ends, a UTF-8 byte-order mark so Excel reads the Arabic names, and a download through a Blob URL and an `<a download>` click. `src/lib/db.ts`: `listAllPlants` and `listAllTasks` read the whole tables in pages of 1,000, the tasks with the plant's tag, site and zone. Settings gets an "Export" card with "Export plants" (`plant-care-plants-<date>.csv`: tag, quantity, species names in English, French, Arabic and Latin-script Arabic, scientific name, cultivar, site, zone, lat, lng, planted on, source, rootstock, ids, created at) and "Export tasks" (`plant-care-tasks-<date>.csv`: plant tag, site, zone, type, title, due on, window end, status, acted at, note, instruction, rule key, ids); the card shows the row count and the file name after each export, or the error. Enum values and column names are the raw database values, so the files are stable and language-independent.
- [x] Zones per site. `supabase/schema.sql` gains the `settings` table (key, jsonb value, same `owner_all` policy as the other tables); the SQL for the existing project is in the ★ step above. `src/lib/db.ts`: `getSetting`, `setSetting`, `loadZones`, `saveZones`, with a `SettingsUnavailable` error when the table is missing. Settings gets a "Sites and zones" card: for Backyard and Farm, the zone list with a Remove button on each, an input with Add, and the zones used on plants but not yet listed as one-tap suggestions. `RecordForm` loads the site's zones and shows them as chips above the Zone field (tap to fill), with the recent values from plants still offered in the field's suggestion list. Removing a zone from the list leaves every plant's zone text as it is. The choice (a table rather than a list derived from plants) is recorded in `docs/DECISIONS.md`.
- [x] Species library. Phase 1 already gives confirm, per-section field editing kept on regeneration, regenerate, and delete when no plant uses the profile; what the spec's Species row still lacked was editing the care calendar and the pests. `src/screens/species/ListCard.tsx` shows either list with an Add button on the heading and an Edit button on each card, and opens `RuleEditor.tsx` or `PestEditor.tsx` in place of the card, one editor at a time on the screen. A rule form has type, age, months (twelve toggles in two rows, `MonthPicker.tsx`), days between waterings and litres (water rules only), days of warning, title and instruction; a pest form has the English and French names, months, symptoms, organic treatment and prevention; each form has Save, Cancel and, for an existing entry, Delete behind a confirm. A rule with the same type, months and age as another is refused, since the two would share their tasks. The whole list is saved as one block through `updateSpeciesField`, so it lands in `user_edits` and a regeneration keeps it as edited (the "edited by you" pill shows on the heading, and the line under the list says so). After a calendar save the app runs `/api/expand` for all plants, with its progress under the list, so the tasks follow the new rules at once. `RuleCard` and `PestCard` are exported from the profile components with an actions slot, and `order.ts` gives the display order to both the read-only sections and the editors.
- [ ] All new strings in `src/i18n/en.ts` and `fr.ts`; the Settings phase card reads Phase 5; version 0.5.0 in `package.json` and `src/version.ts`; README mentions the phase; `docs/DECISIONS.md` lists the deviations and the two follow-ups (the digest and the expansion notes stay English; editing a Claude-written list by hand means a regeneration no longer refreshes it).

## Acceptance tests (run on the phone, installed app on 0.5.0)

1. Settings → Language → Français → the app reloads in French: the tabs read Aujourd'hui, Plantes, Espèces, Réglages; the Today summary line, the task type pills (Arroser, Tailler, Fertiliser…), the plant screen tabs and every Settings card are in French; the species profile text written by Claude stays as it was written. English again the same way. Close and reopen the installed app → the choice is kept.
2. Settings → Export → Export plants → Chrome saves `plant-care-plants-<today>.csv` to Downloads and the card reads "N rows saved as …". Open the file in Excel or Google Sheets → one row per plant, the Arabic name readable (not mojibake), the GPS in two columns, the planting date as `YYYY-MM-DD`, the source. Export tasks → `plant-care-tasks-<today>.csv` → one row per task with the plant tag, type, due date, window end, status, acted date and note; done, skipped and snoozed tasks are included.
3. Before the ★ SQL is run: Settings → Sites and zones shows the "settings table does not exist" notice, and Capture → the record form still suggests the zones used before. After the SQL: the card shows Backyard and Farm with empty lists; add "north terrace" under Backyard and "row 2" under Farm → each appears at once; a zone already used on a plant but not listed appears as a suggestion to tap. Capture → with Farm selected the form shows "row 2" as a chip above Zone; tapping it fills the field; switching to Backyard shows "north terrace" instead. Remove "row 2" → the chip is gone; a plant recorded with "row 2" keeps that zone on its screen.
4. Species → the persimmon → Care calendar → Edit on a rule → change its months and its title → Save → the card shows the new months and the "edited by you" pill; after a moment the plant's Calendar tab (Today → the plant) lists a task for the new rule and none for the old one. Add a rule (a water rule: every 7 days, 20 L, June to September, establishment) → it is listed by month with the "every 7 days" and "20 L" pills. Add the same rule again → the form refuses it ("Another rule already has this type…"). Edit the new rule → Delete this rule → confirm → it is gone. Pests and diseases → Edit a pest → change its months → Save; Add a pest → it is listed by its first month.
5. Species → Regenerate from Claude → confirm → the calendar and the pests stay exactly as edited (the pill stays), the other sections are rewritten and the profile goes back to "AI-written, confirm". One profile call on the Claude Console, about 3 cents.
6. Settings in French → Export plants → the column names and the site and source values are unchanged (English database values), only the card's text is French.
